# Hire Flow — Recruitment CRM + Analytics (Demo)

**By Manuraj M** · [LinkedIn](https://www.linkedin.com/in/manuraj--/) · [GitHub](https://github.com/manu3511)

A recruitment-funnel CRM with IVR-integrated candidate tracking, position-requisition management, and an analytics dashboard — originally built and running in production for a real HR team. **This repo is a self-contained portfolio demo**: same frontend code, seeded with fully fictional data, with no live backend, no real accounts, and no real candidate information anywhere in it.

📄 Full write-up: [CASE_STUDY.md](./CASE_STUDY.md) — the problem, the architecture, and three real engineering bugs I found and fixed (a race condition, a security gap, a bulk-insert failure).

## What's real vs. simulated

| | |
|---|---|
| **UI / logic / RLS-equivalent role gating** | Real — same code that runs in production |
| **Data** | 220 fictional candidates, 6 requisitions, ~700 call logs, generated by `generate-demo-data.js` and bundled at build time |
| **Backend** | None — `src/mockBackend.js` replaces every Supabase/API call with an in-memory store (persisted to your browser's localStorage, so your changes stick across reloads but never leave your browser) |
| **Auth** | 5 fixed demo logins, no real signup/session |

## Run it locally

```bash
npm install
npm start
```

Regenerate the dataset (edit `generate-demo-data.js` first if you want different numbers):

```bash
node generate-demo-data.js
```

## Stack

React · a hand-written PostgREST-subset mock layer (see `src/mockBackend.js`) · originally: Supabase (Postgres + RLS) + FastAPI + Vobiz telephony in production.
